# 徐医校园网助手

这是一个 Chrome Manifest V3 扩展，用于徐州医科大学 DrCOM 校园网网关。扩展默认仅访问 `10.10.10.2`，提供首次安装引导、可恢复的现代认证页、多账号管理、登录/下线、原认证请求暂存并确认、浏览器启动自动登录、定时保活、短时防跳转和脱敏请求日志。1.0.3 修复账号投毒、响应解析与资源耗尽、低风险安全项和请求日志写放大，并完成主要模块拆分；1.0.2 完成全部界面的 WinUI 3 重构与个性化体系：连接状态机、全局单通道登录、智能退避重试、后台重启恢复、强调色取色器、材质与遮罩调节、必应每日壁纸和动画角色登录页。1.0.2 起，门户登录/在线页表面的遮罩与文字颜色始终跟随整体浅/深主题，不再按背景图片亮度自动判定。欢迎页、弹窗、设置页与认证页均适配窄屏、横屏、触控操作和带安全区的移动设备，并共享跟随系统、浅色、深色和自定义背景外观。

当前仓库只维护 `CRX` 中的稳定版 1.0.3。完整功能、架构、数据结构、消息流、测试和发布方式见 [`docs/development-guide.md`](docs/development-guide.md)，产品体验约束见 [`docs/product-design.md`](docs/product-design.md)。贡献前请阅读 [`CONTRIBUTING.md`](CONTRIBUTING.md)，整改与版本变化见 [`CHANGELOG.md`](CHANGELOG.md)。

## 安装与使用

1. 打开 Chrome 的 `chrome://extensions/`，开启“开发者模式”。
2. 点击“加载已解压的扩展程序”，选择 `CRX`。
3. 首次安装会打开欢迎页。连接校园网后点击“打开 10.10.10.2 并登录”。
4. 认证页默认显示扩展提供的现代登录界面；点击右上角“使用原始登录页”可以立即恢复学校原页面。
5. 登录时选择保存账号，之后可以从扩展弹窗或设置页快速登录、切换账号和下线。

如果你临时切回学校原始页面登录，扩展只会把原页面请求中捕获到的账号候选暂存并确认：设置页显示来源、脱敏账号和是否覆盖已有账号，用户点“确认保存”后才写入本地账号；取消、过期或来源变化都会丢弃候选。

现代登录页保留学校页面的常用能力：校园网、联通、电信、移动四种账号类型，保存密码、重置，以及自助服务、账号激活、找回密码和使用说明四个官方入口。在线页默认显示已用时间、总流量、自助服务和“注销并解绑 MAC”；展开后可查看经过脱敏的账号、上下行流量、余额、登录时间及网络信息。设置页“外观与个性化 → 在线信息显示”可以切换经典、完整、简化或隐藏模式。

账号激活、找回密码、自助服务和使用说明仍由学校官方系统处理，扩展只提供带 `noopener noreferrer` 的新窗口链接，不读取这些外部页面。二维码登录和移动端验证码没有复刻；检测到验证码字段时扩展不会遮挡学校控件，只提示继续使用原始页面。

默认网关不需要额外授权。只有用户主动保存其他自定义网关时，扩展才会请求该网关对应的 HTTP/HTTPS 来源；Manifest 中的全主机范围仅用于支持这种运行时可选授权，安装时不会自动获得全部站点访问权。

## 安全与凭据

- 为支持保存账号和自动登录，密码会以明文保存在当前 Chrome 配置文件的扩展 `storage.local` 中；它不是独立加密保险库，也不会上传到项目仓库。
- 默认 DrCOM 门户和接口使用 HTTP，且学校协议把凭据放在 GET 请求参数中。扩展无法把这一既有协议提升为端到端加密，校园网链路、代理或抓包工具仍可能观察到请求。
- 后台把本地存储限制为可信扩展上下文，门户脚本只能调用白名单消息；原页面捕获不能直接覆盖持久账号。但设备失陷、操作系统账号被控制、HTTP 宿主页面脚本或具有高权限的恶意扩展仍可能观察或读取敏感信息。
- 界面、日志和导出默认隐藏密码，日志还会脱敏账号及敏感查询参数。发布、测试和漏洞报告都不要附带真实账号、密码、抓包 URL 或浏览器配置数据。

完整威胁模型和安全报告方式见 [`SECURITY.md`](SECURITY.md)。

## 门户诊断模式

“门户诊断模式”默认关闭。启用后，只有默认门户 `http://10.10.10.2` 的顶层页面会在本机记录经脱敏的页面结构、操作类型和资源元数据；记录只保存在 `chrome.storage.local` 的 `drcomPortalDiagnostics` 键，不会上传。保存上限为总计 1 MiB、最多 10 个会话，单条 DOM 摘要最多 64 KiB。

在设置页的“高级设置”中可开启或关闭模式、查看本地占用、会话数、已淘汰记录数与暂停状态，导出 JSON，或在确认后清空记录。导出固定说明脱敏边界和记录可能不完整；文件仍应在分享前人工复核，不要把它与真实账号、密码、Cookie、浏览器存储内容或原始抓包一起提交到仓库。

## 登录原理与连接恢复

所有界面都把登录交给后台的同一条认证通道，页面本身不直接调用 DrCOM。一次登录依次执行：检查当前会话、解析本次门户 IP、可选查询 MAC、发送 `Portal/login`、结构化解析响应并写入连接状态。只有最后一步会把密码放入学校既有的 HTTP GET 请求；状态检查、门户上下文获取和 `find_mac` 都不包含密码。

现代门户选择“保存账号”时先保存账号再按 `accountId` 登录；取消保存时使用仅存在于本次调用中的临时账号。登录成功后，后台只把不含密码的实际认证身份与本次网络上下文保存到 `storage.session`，供正确下线使用。完整函数调用、请求参数来源和结果判定表见开发指南的[登录原理与调用链](docs/development-guide.md#73-登录原理与调用链)。

- 登录先查询 `/drcom/chkstatus`；已在线时直接返回，不读取门户上下文，也不发送密码。
- 首次登录从当前门户 URL 或首页的 `v46ip`、`ss5`、`v4ip`、`ss3` 静态变量取得实时 IP；没有有效实时/全局 IP 时停止认证，历史账号 IP 不会触发密码请求。启用 `find_mac` 时，有效返回 MAC 会真正进入最终登录请求。
- 弹窗区分检查中、需要登录、登录中、等待重试、需要处理和已在线。
- 任意两个入口同时触发登录时只执行一个真实 DrCOM 请求。
- 临时网络错误从 30 秒开始指数退避，最长等待 5 分钟；密码或账号错误会停止自动重试并提示人工检查。
- 跳转保护、连接恢复状态和本次实际认证身份保存在 `storage.session`，后台服务被 Chrome 回收后不会立即丢失。注销不回退到界面选择的其他账号；只有状态复核明确离线才清除身份。
- 注销使用当前活动身份和本次网络上下文：有有效 MAC 时先请求 `unbind_mac`，未能确认离线则回退完整 `Portal/logout`，并按 300、800、1500 毫秒复核；接口返回成功但状态仍为在线或未知时不会伪造离线。
- 保活只在状态明确为离线时恢复登录；超时、网络错误和异步门户空壳均保持未知状态，不发送凭据。
- 保活任务在浏览器启动和扩展更新时自检，配置未变化时不会重复清除和创建。
- 自定义背景与每日壁纸保存上限约 1.9 MB（受浏览器内联样式单值上限约束）；超限原图会从高质量档开始多轮压缩并逐级缩放，完整扩展状态超过安全预算时会在写入前给出明确提示。

## 开发

项目不依赖第三方 npm 包。需要 Node.js 20 或更高版本：

```powershell
npm run verify
```

该命令会执行静态检查、单元测试、真实浏览器布局测试和确定性打包验证。修改后在 `chrome://extensions/` 刷新扩展，再分别验证：首次安装欢迎页、现代/原始认证页切换、校园网/运营商后缀、多账号切换、登录、下线、状态检测、保活、防跳转和危险操作取消。

## 目录

- `CRX/manifest.json`：扩展权限、入口和版本。
- `CRX/background.js`：经典 Service Worker 的依赖加载与 Chrome 事件注册。
- `CRX/background/state-store.js`：schema 13、存储迁移、独立请求日志键、连接 Session 和串行写入。
- `CRX/background/portal-context.js`：安全解析当前门户运行上下文和实时 IP，不执行页面脚本。
- `CRX/background/drcom-client.js`：DrCOM 请求构造、结构化响应解析和日志脱敏。
- `CRX/background/account-service.js`：自然键去重、账号生命周期和网络参数更新。
- `CRX/background/connection-service.js`：登录单通道、活动身份、退出、退避与保活。
- `CRX/background/portal-service.js`、`message-router.js`：门户注入、网页来源校验和消息权限。
- `CRX/account-utils.js`：跨后台、页面和测试共享的账号解析工具。
- `CRX/portal-session.js`：在线状态字段规范化、单位换算和账号/网络标识脱敏。
- `CRX/confirm-dialog.js`：统一危险操作确认。
- `CRX/design-tokens.css`：基于 WinUI 3 官方主题资源的共享语义令牌、控件层和深浅色规则。
- `CRX/background/wallpaper-service.js`：每日壁纸（必应）获取与本地缓存，仅在用户授权后联网。
- `CRX/fonts/segoe-fluent-icons.ttf`：Segoe Fluent Icons 图标字体，用于离线渲染界面字形；字体版权归微软所有，参照 WinUIonWeb 项目以随包分发方式用于本地界面还原，不用于其他用途。
- `CRX/appearance.js`：外观配置规范化、背景安全校验与跨页面主题应用。
- `CRX/welcome.*`：首次安装欢迎与网关引导。
- `CRX/portal-ui.js`：可测试的账号解析、登录数据模型和安全模板。
- `CRX/portal-capture.js`：原门户请求候选暂存、可信用户事件窗口和设置页确认入口。
- `CRX/portal-modernizer.js`：可恢复认证页覆盖层、现代登录流程和在线状态视图。
- `CRX/popup.*`：扩展弹窗。
- `CRX/options*.js`：设置页初始化、刷新控制、捕获确认、外观图片处理、账号、常用自动化和折叠高级设置。
- `docs/development-guide.md`：功能、架构、数据、接口、开发、测试和发布说明。
- `scripts/*.js`：浏览器进程清理、分组测试、确定性打包和发布标签校验。
- `tests/*.test.js`：无需安装第三方测试库即可运行的后台、连接状态和界面逻辑回归测试。

## 发布

先执行 `npm run verify`，再按目标打包，产物在 `dist/`（ZIP + SHA-256，根目录直接包含 `manifest.json` 与 `LICENSE`）。本地开发不做打包：直接在 `chrome://extensions/` 以未打包目录加载 `CRX/`，仓库中的 manifest 保留开发用 `key` 以维持稳定扩展 ID。

**上架 Chrome Web Store** 使用 `npm run package`（等价 `npm run package:chrome`），产出 `dist/drcom-xuzhou-medical-chrome-1.0.3.zip`——商店校验不允许 manifest 含 `key`（商店会为扩展分配自己的 key 与 ID），该包从主清单派生并自动删除 `key`。

Firefox 使用 MV3 兼容构建：`npm run package:firefox` 产出 `dist/drcom-xuzhou-medical-firefox-1.0.3.zip`。它基于同一份 `CRX/` 源码与白名单，仅替换 manifest：移除 Chrome 的 `key`、`options_page` 改用 `options_ui`、加入 `browser_specific_settings.gecko` 元数据（要求 Firefox 118+，因连接状态使用 `storage.session`）。代码中 Chrome 专有 API（如 `storage.local.setAccessLevel`）均做了能力检测，不支持时自动跳过。

创建本地标签或未来接入标签工作流前运行：

```powershell
npm run verify:release -- v1.0.3
```
