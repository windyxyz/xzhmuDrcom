# 门户诊断模式与异步接管修复设计

## 1. 背景

徐州医科大学当前门户 `http://10.10.10.2/` 不是在初始 HTML 中直接输出登录或注销界面。入口页先加载 `a41.js` 和按网络范围选择的模板配置，再通过 `/drcom/chkstatus` 等 JSONP 请求判断状态，最后异步加载 `pc.js`、`pc_1.js`、`pc_2.js` 或 `pc_3.js` 并写入页面。

扩展的 `portal-modernizer.js` 目前只在 `DOMContentLoaded` 后识别一次密码框或在线文案。如果学校脚本此时仍在查询状态，页面还是空的，扩展会恢复原页面并永久停止识别。因此即使“接管并美化认证页”已启用，用户仍会看到学校原始界面。

对实时门户公开资源的只读检查确认了以下原页面能力：

- 登录页：账号、密码、运营商、保存密码、重置、登录；
- 辅助入口：账号激活、使用说明、找回密码、自助服务；
- 可选入口：二维码登录和移动端验证码；
- 在线页：在线状态、已使用时间、已使用流量、自助服务；
- 下线：确认后注销，并在当前配置下解绑 MAC；
- 状态页：登录成功、登录失败和可理解的失败提示；
- 状态接口还提供上下行流量、登录时间、计费、IPv4/IPv6 和接入网络字段。

本规格是已批准三阶段工作的第一阶段，只实现“本地诊断模式”和“异步接管修复”。门户核心能力复刻以及外部账号服务复刻将在真实样本采集完成后分别设计和实现。

## 2. 目标与非目标

### 2.1 目标

1. 学校页面异步生成登录或在线 DOM 后，扩展能够可靠识别并接管。
2. 用户点击“使用原始登录页”后，本次页面保持原始界面，不再次接管。
3. 提供默认关闭的门户诊断模式，在没有互联网时仍能把脱敏记录写入本机扩展存储。
4. 记录页面结构、交互顺序、DOM 状态变化、资源请求元数据和扩展侧错误，帮助还原学校门户功能。
5. 提供本地 JSON 导出、清空、容量显示和严格的缓存淘汰规则。
6. 诊断失败不得阻断学校原页面或认证流程。

### 2.2 非目标

- 本阶段不复刻账号激活、找回密码或自助服务业务。
- 本阶段不代替用户提交登录、注销、验证码或密码修改。
- 不记录输入值，不解密或导出扩展保存的密码。
- 不把诊断数据发送到网络、云服务或 GitHub。
- 不依赖 Edge 控制连接；断网时采集必须由扩展独立完成。

## 3. 总体架构

### 3.1 组件

- `CRX/portal-modernizer.js`
  - 把一次性识别改为异步页面识别状态机。
  - 保留原门户捕获和现代界面恢复能力。
- `CRX/portal-diagnostics.js`
  - 运行在内容脚本隔离世界。
  - 监听经过筛选的 DOM、交互、资源和错误事件。
  - 只发送已脱敏、限长的诊断记录。
- `CRX/background/diagnostics-service.js`
  - 管理诊断设置、会话、容量、淘汰和读取。
  - 使用独立存储键，不把大量记录塞入账号状态。
- `CRX/background/message-router.js`
  - 增加诊断状态查询和追加消息。
  - 读取、设置、导出和清空只允许扩展自身页面调用。
- `CRX/options.html`、`CRX/options.js`、`CRX/options.css`
  - 在高级设置中提供诊断开关、容量状态、导出和清空操作。
- `CRX/manifest.json`
  - 在门户现代化脚本之前加载诊断内容脚本所需的本地文件。

不向页面主世界注入网络代理，也不修改学校的 `fetch`、XHR 或 JSONP 实现。资源观察使用 `PerformanceObserver` 和 DOM 中新增的脚本、图片、样式资源，降低对原页面的干扰。

### 3.2 数据流

1. 内容脚本启动后向后台查询诊断模式是否启用。
2. 关闭时立即退出，不注册长期监听器。
3. 开启时建立本次页面会话，记录初始页面摘要。
4. 捕获事件后先在内容脚本中脱敏和限长，再发送到后台。
5. 后台再次执行结构校验、脱敏和字节预算检查，然后写入独立存储。
6. 设置页从后台读取统计信息；导出时在扩展页创建 JSON Blob，由用户保存到本机。
7. 清空使用现有统一危险操作确认对话框。

## 4. 异步接管状态机

内容脚本在 `DOMContentLoaded` 后按以下顺序运行：

1. 安装原门户登录/注销捕获逻辑。
2. 获取安全门户配置和外观配置。
3. 若现代化关闭，保持原页面并结束接管流程。
4. 在首次识别前建立 `MutationObserver`，观察 `document.documentElement` 的子树变化。
5. 立即执行一次页面识别；后续 DOM 变化使用短时间合并，避免重复并发识别。
6. 识别到密码输入框时进入 `login` 状态；识别到注销控件或在线文案时进入 `online` 状态。
7. 识别成功后先断开“等待接管”观察器，再挂载现代界面，避免扩展自己的 DOM 触发递归。
8. 未识别的错误、广告或中间状态保持原页面，诊断模式可继续采集。
9. 用户点击“使用原始登录页”时设置本页内存标志，移除现代层并禁止本页重新接管。

用于捕获学校原请求的既有观察器与“等待接管”观察器职责分离。前者在恢复原页面后仍可工作，后者在成功接管或用户明确恢复后停止。

## 5. 诊断数据模型

独立存储键为 `drcomPortalDiagnostics`，格式版本从 `1` 开始：

```text
{
  version: 1,
  enabled: false,
  limitBytes: 1048576,
  totalBytes: 0,
  droppedRecords: 0,
  sessions: [{
    id,
    startedAt,
    endedAt,
    origin,
    pageKind,
    records: [{ at, type, data }]
  }]
}
```

记录类型限定为：

- `page`：URL、标题、识别状态和脱敏 DOM 摘要；
- `action`：click、submit、change、focus 等动作及目标结构；
- `mutation`：合并后的 DOM 结构变化摘要；
- `resource`：资源协议、主机、路径、发起类型和可用状态；
- `error`：诊断脚本自身错误、资源元素错误和消息写入错误。

缓存规则固定如下：

- 总上限 `1 MiB`；
- 最多最近 `10` 个会话；
- 单个 DOM 摘要最多 `64 KiB`；
- 单条普通记录另有限长，异常大字段在进入后台前截断；
- 每次写入按 UTF-8 编码后的实际 JSON 字节数计算；
- 超限时先删除最旧会话，再删除当前会话最旧记录，直到满足上限；
- 淘汰数量累加到 `droppedRecords`；
- 如果浏览器总存储接近配额，停止新增诊断记录，但不修改账号、密码、背景或其他设置。

`enabled` 与记录放在同一独立键中，但“清空记录”只清空会话和统计，不改变开关。

## 6. 隐私与脱敏

### 6.1 永不记录

- 任意输入框、文本框和选择控件的值；
- 账号、密码、新旧密码、验证码、短信码和 Token；
- 手机号、证件号、电子邮件；
- 完整 IPv4、IPv6、MAC；
- Cookie、浏览器存储、扩展账号状态和浏览器历史；
- 请求体、响应体和完整敏感查询字符串。

### 6.2 可以记录

- 标签名和限长的可见控件文案；
- `id`、`name`、`type`、`role`、`aria-label`、`data-localize`；
- 表单动作类型和目标路径；
- URL 的协议、主机和路径；
- 明确允许的协议查询键值，例如 `c=Portal`、`a=login`、`a=logout`、`ver` 和 `jsVersion`；
- 其他查询参数只保留键名，值统一为 `[REDACTED]`。

文本在记录前清理账号后缀、IP、MAC、手机号、电子邮件、长数字串和高熵长字符串。页面和后台各执行一次脱敏，导出前再执行最终校验。

页面本身是不可信来源。诊断记录只作为调查证据，不能触发账号修改、配置修改、登录或下线。

## 7. 设置页交互

高级设置新增“门户诊断模式”区域：

- 开关：默认关闭；开启前说明会在本机记录脱敏页面行为。
- 状态：显示当前是否采集、会话数量、已用字节、`1 MiB` 上限和淘汰数量。
- 导出：生成带版本、导出时间和脱敏声明的 JSON。
- 清空：显示将删除的会话数量和占用空间，默认焦点在取消按钮。
- 存储不足或记录失败时显示可理解错误，但不把诊断失败误报为认证失败。

诊断模式不自动禁用现代界面。需要采集学校原页面时，用户在现代界面点击“使用原始登录页”；本次页面随后保持原界面并继续诊断。

## 8. 消息与权限边界

网页来源仍必须通过既有严格校验：扩展自身 ID、顶层 frame、精确 `http://10.10.10.2` 来源以及当前标签仍在该来源。

新增网页白名单动作仅包括：

- `diagnostics:status`：返回布尔开关和非敏感会话标识；
- `diagnostics:start`：建立本页诊断会话；
- `diagnostics:append`：追加一条已限长记录；
- `diagnostics:end`：结束本页会话。

设置、读取全部记录、导出和清空动作拒绝网页内容脚本，只允许扩展自身页面。

不新增网络权限、下载权限或任意站点权限。

## 9. 故障处理

- 后台服务休眠时，`chrome.runtime.sendMessage` 会唤醒服务；失败记录不阻断原页面。
- 内容脚本只保留小型内存队列用于合并突发事件，不在页面内持久化敏感数据。
- `PerformanceObserver` 不可用时跳过资源观察，DOM 和动作采集继续工作。
- 存储写入失败时记录一次本地状态并停止继续写入，避免错误循环。
- 页面结构始终不明时保持学校原页面，不显示空白现代层。
- 现代界面挂载失败时回滚到原页面。
- 扩展被重新加载时，未写入的少量内存事件允许丢失；已写入会话仍可导出。

## 10. 测试策略

测试驱动实现，先观察新增测试按预期失败，再写最小生产代码。

### 10.1 单元与契约测试

- 初始空 DOM 在异步出现密码框后接管登录页；
- 初始空 DOM 在异步出现注销控件或在线文案后接管在线页；
- 用户恢复原页面后，后续 DOM 变化不重新接管；
- 诊断关闭时不建立会话和监听器；
- 输入值、账号、密码、验证码、IP、MAC、手机号、邮件和 Token 被删除；
- 协议动作查询参数保留，其他参数值脱敏；
- 网页只能追加，不能读取、导出、设置或清空诊断数据；
- `1 MiB` 总上限、10 会话限制、64 KiB DOM 限制和 UTF-8 字节计算；
- 超限按最旧优先淘汰并累计计数；
- 清空不关闭诊断模式；
- 导出文件不含被禁止的敏感字段和值。

### 10.2 浏览器测试

- 真实异步 DOM 页面最终渲染现代登录界面；
- 真实异步在线页面最终渲染现代在线界面；
- 点击“使用原始登录页”后页面保持原样；
- 开启诊断后完成操作并导出 JSON，关闭后无新增记录；
- 诊断脚本异常时原页面仍可操作且没有横向溢出。

### 10.3 学校真实样本

实现后执行以下人工采集：

1. 重新加载未打包扩展并开启诊断模式。
2. 在当前注销页采集在线信息和原注销流程。
3. 用户本人点击学校注销按钮；此操作会断开互联网，但本地网关和扩展存储仍可工作。
4. 在未登录页依次操作运营商、账号、密码、保存密码、重置、辅助入口等控件；不要求提交真实凭据。
5. 用户把未登录首页保存为 MHTML。
6. 恢复网络后从设置页导出诊断 JSON。
7. 将 MHTML 与 JSON 放入获准工作区，先脱敏再生成回归夹具。

## 11. 验收标准

- 当前学校门户异步渲染后可被现代界面接管。
- 恢复原页面在本次加载中稳定有效。
- 诊断关闭零记录，开启后断网可写入本机。
- 导出 JSON 不包含输入值或定义中的敏感数据。
- 缓存始终不超过 `1 MiB`，会话不超过 10 个，单 DOM 摘要不超过 64 KiB。
- 存储或诊断错误不影响原门户登录、注销和页面恢复。
- 新增定向测试以及完整 `npm run verify` 全部通过。

## 12. 后续阶段边界

第二阶段基于真实样本复刻门户核心功能：登录、运营商、在线详情、成功/失败、注销和解绑 MAC。

第三阶段复刻学校外部账号服务：账号激活、找回密码和自助服务。扩展可以提供原生流程，但验证码、短信码和最终密码操作由用户本人完成；敏感数据只发送到学校官方接口，不保存、不记录、不导出。
