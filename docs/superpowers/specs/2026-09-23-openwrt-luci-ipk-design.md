# 徐医校园网 OpenWrt LuCI 插件设计

## 目标与迭代范围

为 OpenWrt 系路由器提供可通过 `opkg` 安装的 LuCI 图形界面，首轮以用户的 JDCloud RE-CS-02 / LibWrt 25.12.1 为目标验证。首轮交付 `Architecture: all` 的 `.ipk`，不要求在路由器上安装编译工具链。

首轮提供手动状态查看、账号配置、登录、注销/终端解绑。页面进入时查询一次状态，用户可手动刷新；不加入自动登录、定时保活、防火墙改动或网络接口变更。登录/注销只在用户点击后执行，未知状态不得显示为成功。

独立端口的管理页面记录为后续迭代。它需要单独设计认证、会话、CSRF 防护和监听范围；首轮复用 LuCI 现有认证，不额外开放 HTTP 服务端口。

## 组件与调用链

- LuCI JavaScript 页面：显示状态、账号/后缀/门户地址配置、手动登录和注销/解绑操作。
- Ucode RPC 后端：只暴露固定的 `status`、`save_config`、`login`、`logout` 方法；每个方法校验输入并返回结构化结果。
- rpcd ACL：只授权上述 RPC 方法，不授权 `file.exec`、任意 shell、通用文件读取或网页直接读写 UCI。
- 现有 `SSH/drcom-xzhmu.sh`：继续作为认证协议核心。仅增加可选的 UCI 配置读取入口；不启用该入口时，现有 `/etc/drcom-xzhmu.conf` 行为保持兼容。
- `.ipk`：包含 LuCI 页面、菜单、ACL、Ucode 后端、脚本与初始非敏感设置；依赖 LuCI 与 Ucode RPC 运行时。

RPC 后端以参数数组执行脚本，命令只能是固定的 `status`、`login` 或 `logout`，不得拼接 shell 命令字符串，也不得接受任意脚本参数。耗时操作期间前端锁定重复提交。

## 配置与凭据保护

账号、密码、后缀与门户地址保存在 `/etc/config/drcom-xzhmu`，文件权限设为仅 root 可读写。LuCI 的通用 UCI ACL 不开放给页面；Ucode 后端通过专用方法访问设置。

读取设置时可以返回账号、后缀、门户地址及“密码已设置”标记，但绝不返回密码。密码输入框每次为空；保存时空密码表示保留现有密码，用户明确输入新密码才替换。输入字段拒绝换行及不支持的控制字符，门户地址限制为合法 HTTP/HTTPS 地址。

凭据仍以明文存在路由器本地受限文件中；学校门户的 Dr.COM 登录仍使用现有 HTTP GET 协议。产品说明如实保留这两个限制。

## 页面行为与错误处理

- 状态显示 `online`、`offline`、`unknown` 三态；状态未知时不自动发起登录，也不将它转换为离线。
- 保存配置、登录和注销分别显示完成或失败；展示脱敏的脚本消息，不返回密码、认证 URL 或原始 HTTP 响应正文。
- 注销成功只以现有脚本确认离线的结果为准；脚本报告未知/仍在线时，页面如实提示未确认。
- 页面初次打开自动刷新一次，后续仅响应用户的刷新动作，不后台轮询。
- 页面适配 LuCI 常规桌面与移动视口；采用系统 LuCI 组件样式，不另做独立主题。

## 打包与设备验证

首轮仅承诺兼容已确认的 LibWrt 25.12.1、`opkg`、LuCI 组合。包标记为架构无关；安装依赖由包元数据声明。包构建不改动扩展版本号和现有 Chrome/Firefox 发布产物。

设备验证覆盖本地 IPK 安装、依赖解析、LuCI 菜单和页面加载、配置写入权限、密码不回显、固定 RPC 方法与 ACL、状态接口和卸载/升级时保留配置。首次设备验收不代替用户执行真实登录或注销，不使用真实校园网凭据作自动化测试；真实登录/注销由用户在界面上手动验证。

## 非目标

- 首轮不实现独立端口管理页面、独立认证系统或 TLS 服务。
- 不改变浏览器扩展登录/注销逻辑、自动登录、保活策略、网关参数或桌面扩展版本。
- 不访问或改写防火墙、WAN/LAN、接口热插拔或计划任务配置。
- 不将用户名、密码、网络标识或认证 URL 写入日志、状态接口或测试样本。
